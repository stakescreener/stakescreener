Modifications for the static Apache/cPanel export
=================================================

Date: 2026-08-16

- Split the original single-file application into index.html, slog.css and
  app.js without changing the analyzer calculations or data-source logic.
- Replaced the Chart.js CDN reference with a local Chart.js 4.4.1 file.
- Replaced the Google Fonts import with local Inter and Space Mono files.
- Made every packaged asset reference explicitly relative for subfolder use.

Original source:
https://github.com/hexstakeanalyzer/Hex-Stake-Analyzer


Additions for stakescreener.com (2026-08-16)
--------------------------------------------
- Added denarnica.js and denarnica.css: a read-only wallet balance overview.
  Token lists come from the Blockscout API, native balances from JSON-RPC and
  prices from DexScreener (deepest pool per token; below $2,000 of liquidity a
  token is listed without a USD value). No wallet connection, no writes, no
  storage.
- app.js and slog.css are unchanged from the upstream export; the addition
  wraps go() at runtime rather than editing it, so upstream updates can be
  dropped in without merging.

Fixes found while testing against a live wallet (2026-08-16)
-----------------------------------------------------------
Three separate faults, none of which produced an error message:

1. The section was injected inside #dash, a container hidden until an analysis
   finishes, so it rendered correctly into something invisible. Moved out.

2. DexScreener's /latest/dex/tokens caps the RESPONSE at 30 pairs, not 30
   tokens. Measured: 30 addresses -> 30 pairs covering 5 distinct tokens;
   a single address (HEX) -> 19 pulsechain + 11 ethereum pairs. Tokens with
   many pools starved both the other tokens and the other chain. Replaced with
   /tokens/v1/{chainId}/{addrs}, which is chain-scoped and returns the top pool
   per token.

3. The two block explorers name the same field differently:
   api.scan.pulsechain.com -> token.address
   eth.blockscout.com      -> token.address_hash
   Reading only the first gave every Ethereum token an empty address, so every
   lookup missed and the entire Ethereum side showed as unpriced. Both names
   are now accepted.

Shareable wallet-set codes (2026-08-16)
---------------------------------------
koda.php stores a set of addresses outside public_html and returns a 10-character
code, restoring the feature GoPulse.com had before it shut down. A short code
cannot contain the data (20 bytes per address), so it can only ever be a key —
hence the small server side. Stored: addresses only, no IP, no user agent.
Deleted after 180 days; re-saving the same set returns the same code.
Alternative without any storage: /#w=0xaddr,0xaddr — the fragment is never sent
to a server.

Wallet names (2026-08-16)
-------------------------
Click the short address in a wallet card to name it (e.g. "S/1 Hex Stakes").
Names live in localStorage on the device AND travel inside a saved code, so a
set imported in another browser arrives already labelled. Server side they are
control-character stripped and capped at 40 characters.

Collapse, refresh, build number (2026-08-16)
--------------------------------------------
- Each wallet card has a chevron that collapses it to a single line: name,
  address, Rename and the total. The choice is remembered per address in
  localStorage (gopulse_collapsed) and survives a reload.
- Refresh button: adding a wallet chip does not re-run the analyzer, so the
  section could show one card while the chips showed two — and a missing card
  meant no Rename button for that wallet. Refresh reloads balances only.
- The build number is printed next to the section title. Twice during
  development a fix appeared not to work purely because the browser was serving
  a cached index.html; there was no way to see that from the screen. The
  .htaccess now also sends no-cache for .html and a long max-age for the
  versioned assets.

Own wallet list, up to 30 (2026-08-16)
--------------------------------------
app.js refuses more than 10 wallets per session ("Maximum 10 wallets per
session") because a HEX stake scan is expensive. Reading balances is not, so
this section now keeps its OWN list in localStorage (gopulse_wallets, cap 30)
with its own add field and a per-card remove button. The first 10 entries are
mirrored into the analyzer's own `wallets` array so stake analysis still works
on them, and anything typed into the analyzer's field is merged back into our
list after go() — the two never silently disagree.

app.js remains untouched: raising its limit there was considered and rejected,
because it would break the rule that a new upstream export can simply be copied
over this one. koda.php MAX_ADDRS raised 10 -> 30 to match.

Ecosystem ticker, manual tokens, data status (2026-08-22)
---------------------------------------------------------
Three ideas taken from hexologist.com (HEXO Market Lab) after reviewing it:

- Ecosystem ticker at the very top: pHEX, eHEX, PLS, PLSX, INC, PRVX with
  price and 24h change. Prices come from DexScreener, deepest pool per token,
  same rule as everywhere else. Token addresses were verified against
  /tokens/v1 on 22.8.2026, not guessed.
- "Add token by contract": a token the block explorer does not return can be
  added by hand. Read directly from the contract (symbol, decimals,
  balanceOf) over JSON-RPC. A zero balance is not shown. Stored in this
  browser only.
- Data status line: which source, when fetched, how many priced vs unpriced,
  and whether any wallet's token list came back incomplete. Their principle,
  worth copying: if data is stale, partial or unavailable, say so instead of
  letting it look fresh.

NOT taken: the technical-analysis apparatus (regime, breakout pressure,
patterns, price simulator). Factually hedged or not, it invites trading, and
this site sits under the same s.p. as mojdelez.si.

Ticker icons (2026-08-22)
-------------------------
Token logos are stored LOCALLY in slike/zetoni/ because the Content-Security-
Policy allows img-src 'self' data: only — a CDN URL would simply be blocked.
Downloaded once from the DexScreener CDN and served from this site.

Two things went wrong first, both worth remembering:
- Requesting the CDN with ?format=png returns HTTP 422 and a JSON error, not
  an image. The plain URL without query parameters returns a proper PNG.
- Running the downloaded PNGs through `sips -Z 96` produced files that loaded
  fine (naturalWidth 96) but rendered as empty circles: the palette/alpha was
  mangled. The originals are already 200x200 and ~8-12 KB, so they are now
  served untouched. Checking img.complete && naturalWidth > 0 was NOT enough
  here — the image was "loaded" and still invisible.

Summary cards, totals, validators (2026-08-22)
----------------------------------------------
- Stake Value and Wallet Balance are MIRRORED from the analyzer's own cards,
  not recalculated here. My price source differs from his, so computing them
  myself would put two different numbers for the same thing on one screen and
  nobody would know which is right. If a card is missing, mine shows "—" and
  "available after Analyze" — never a zero.
- Total = wallets + stakes + validators. The three parts are disjoint (liquid,
  staked, locked), so nothing is double counted. Labelled an approximation
  because the price sources are not the same and validators are typed in.
- Validators: count is entered by hand, 32M PLS per validator is fixed, value
  uses the on-chain PLS price from the ticker. It cannot be read from chain —
  the validators run at a provider and are not tied to any wallet address.
  The watchdog solves it the same way (VALIDATOR_COUNT in .env), so both sides
  stay consistent. The count travels inside a shared code (koda.php field
  "val"), otherwise the same code would give a different total elsewhere.
- Mobile: the five-column table scrolls horizontally with a STICKY first
  column, so the token name stays visible while scrolling. owner preferred this
  over breaking rows into blocks.

--- 23.8.2026 · gas za send PLS + osvezevanje na 10 s -------------------------

Kartica GAS ima zdaj dve vrstici namesto ene:

    ≈ 17 PLS ($0.0002) · send PLS      21.000 gasa — TOCNO, fiksna cena prenosa
    ≈ 120 PLS ($0.0016) · menjava     150.000 gasa — PRIBLIZEK, odvisen od poti

Send je prvi, ker je to tisto, kar clovek dejansko naredi najveckrat.

Gas in blok se osvezujeta vsakih 10 s. Promet NE — DeFiLlama racuna 24-urno
okno, ki se v desetih sekundah ne premakne, zato gre le vsak 30. utrip (~5 min).
Osvezevati podatek pogosteje, kot se spreminja, ni svezina, ampak samo promet.

TRI STVARI, KI SO MORALE BITI RESENE, DA OSVEZEVANJE NI SKODLJIVO:

1. Trak se zgradi ENKRAT, nato se spreminja samo besedilo v vozliscih.
   Ponoven izris vsakih 10 s bi pomenil, da trak vsakih 10 s izgine in se vrne.

2. Utrip se USTAVI, ko zavihek ni viden (visibilitychange). Brez tega bi odprt
   zavihek v ozadju do konca dneva poslal ~26.000 zahtevkov na tuja javna RPC
   vozlisca za podatek, ki ga nihce ne gleda. Ob vrnitvi se osvezi takoj.
   Preverjeno v zivo: v skritem zavihku se blok NI premikal, po
   visibilitychange se je v 25 s premaknil za 7 blokov.

3. Ob neuspehu se stara vrednost OHRANI, kartica pa dobi razred `zastarelo`
   (oranzen rob, bleda stevilka) in vrstico "zadnji uspeh pred N s".
   Razlika med "veriga javlja 0" in "nisem je uspel vprasati" je pomembna;
   izpis "—" bi ju zlil v isto.

Vrednost ob DEJANSKI spremembi na kratko posvetli (`.utrip`, 0,7 s). Brez tega
se ne loci "osvezuje se" od "obticalo je". Ob nespremenjeni stevilki utripa ni —
to bi bila lazna zivahnost. Upostevan `prefers-reduced-motion`.

Modulska spremenljivka se imenuje `netUI`, ne `net`: v header() ze obstaja
lokalni `net` = element .net-trak. Ono je skatla, to je vsebina.
